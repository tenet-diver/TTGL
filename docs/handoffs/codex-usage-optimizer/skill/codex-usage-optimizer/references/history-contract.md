# Optimization history contract

Keep independent decision, implementation and evaluation states with an append-only audit trail. Accepted does not mean implemented or effective. Retain declined/deferred versions, source evidence and reasons; record actual state updates through structured receipts and idempotency keys.

Before applying a selected change, define a comparison against a stable tool/server/operation ID. Record before/after effective profile hashes, task/repo/version filters, fixed windows or paired tasks, sample/coverage requirements and quality gates. Generate parameterized read-only SQL through the integration's validated query builder. Store SQL/parameters/schema/compiler/data-snapshot hashes and baseline result; do not run arbitrary log-derived SQL or shell.

After application verify preimage/postimage, actual effective config and activation in a real invocation. Only then report implemented and start treatment collection. Unknown exposure remains unknown. A user/agent applying a change manually must provide equivalent verifiable evidence; a prose completion claim is not sufficient. A changed patch/scope needs a new reviewed proposal version.

Compare payload estimates and tool durations at tool level; model usage/cost and task success at the corresponding whole-task scope. Preserve signed differences, missing counts, failures, sample sizes and confounds. A quieter tool is not necessarily faster. Fewer calls can reduce totals without improving per-call behavior. Independent quality checks determine whether a resource reduction is useful.

Keep results versioned and forecasts immutable. A later technique or overlapping change receives its own profile/arm; do not sum credited savings. Re-evaluation is read-only unless a new trial is explicitly selected. Rollback requires matching managed preimages and must not overwrite later user changes.
