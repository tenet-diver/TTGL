# Metering Codex while using a ChatGPT subscription

**Yes: use the official Codex CLI/SDK with supported ChatGPT login. A separately
billed API key is not required to collect token usage.** The earlier pilot used
a different platform interface and had no exported counters; that is not a
general limitation of subscription-backed Codex.

The [official-source review](codex-metering-evidence.md) verifies the interfaces
against pinned sources and schemas generated by the installed CLI 0.163.0.
The [runtime diagnosis](codex-runtime-metering.md) separates authentication from
the current local execution failure.

## Reuse existing software

The official CLI and TypeScript SDK expose usage events and continued threads.
Use them as the coding harness. Use [ccusage](https://github.com/ccusage/ccusage)
for independent aggregation of retained Codex logs. The inspected current
release, **20.0.44**, is MIT-licensed and supports Codex session/model reports,
cumulative deltas, inherited-history handling and compaction records. Its Codex
log support is labelled experimental, so retain a validation against raw records.

On a normally configured Codex installation:

```bash
npx --yes ccusage@20.0.44 codex session --json --offline
```

This exact release was installed and executed here. It returned an empty session
list because this managed runtime exposes no local rollout logs for the prior
collaboration trials. Its displayed zero totals mean **no discovered records**,
not zero inference or a free experiment. Source and package observations are in
[ccusage-sources.json](ccusage-sources.json).

## Collect three distinct measurements

| Measurement | Source | Valid interpretation |
|---|---|---|
| Input, cached input, output and reasoning breakdown by model | Codex events/rollouts; ccusage aggregation | Observed token resource use when records are complete |
| Estimated subscription credits and estimated USD where returned | Official app-server `account/usage/read` with the task's `threadId` | Provider-estimated usage, subject to account availability |
| API-equivalent USD | Observed tokens multiplied by versioned model/tier prices; ccusage | A pricing scenario, not a subscription invoice |

After normal initialization/authentication, the app-server request is:

```json
{"id":1,"method":"account/usage/read","params":{"threadId":"THREAD_ID"}}
```

The installed protocol includes `estimatedUsageCreditsMicros`, nullable
`estimatedUsageUsdMicros` and per-model/reasoning-effort/speed groups. The account
may return no thread estimate, and this live request has not been validated in
the managed runtime. Never replace missing estimates with zero. Parent/child
inclusion in the backend estimates is not established; do not blindly add both.

A fixed subscription fee does not fall merely because fewer tokens are used.
For subscription economics, measure successful tasks per credit or quota window
and state how the monthly fee is allocated. To claim full deployment savings,
also include local compute, tools, storage and any training. Separate these
quantities rather than describing ccusage's `costUSD` as money actually charged.

## Accounting checks before a benchmark

1. Create fresh, independent controller and expert threads; record their IDs
   against each task and condition. Keep model, effort and speed fixed or record
   changes explicitly. Do not mix research overhead with scored task work.
2. Run a small validation with a resumed controller and a resumed expert. The
   current CLI emits cumulative thread snapshots at completion: 200 followed by
   230 represents 230 total, not 430. Deduplicate per-response records or use
   validated thread deltas. Replayed parent context is not new child usage.
3. Reconcile the event ledger with retained logs and, when available, the backend
   thread estimate. Include retries, failures and compaction. Preserve incomplete
   observations and suspected resets explicitly. Some missing CLI notifications
   serialize as all-zero usage; zero alone is not evidence of free inference.
4. Keep cached input within input and reasoning output within output. Do not add
   every displayed category. Report model-specific tokens before applying prices.
5. Freeze the validated accounting rules and then run the paired software-task
   comparison. Report quality alongside tokens, estimated credits and the
   separately labelled price scenario.

The TTGL adapter distinguishes per-turn usage from Codex's cumulative snapshots
and journals raw observations, validated deltas and accounting gaps by model. Existing pilot files remain unchanged: no attribution can
be reconstructed from absent records. The subscription path is appropriate for
new runs once a live metering preflight succeeds.

## Current runtime blocker

`codex login status` recognizes ChatGPT authentication here. The native CLI
nevertheless fails before inference because its runtime home is read-only; the
inspected startup code requires writing an installation-ID file there. The
usual session directories are absent. This calls for a properly writable Codex
runtime or a platform-provided usage export, not purchasing API access merely
to obtain counters. Authentication files were not copied or manually opened,
and the filesystem restriction was not bypassed.
