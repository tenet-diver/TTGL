# Luna-maintained Smallville versus TokenEconomizer: final results

**Complete, 9 November 2026: 72 coding assignments, all passing their selected task tests.**
Every task used the same Sol solver; Luna only maintained memory. Two common-
interface blocks used the same 8 deterministically selected public HumanEval
functions, plus a separately registered later-period Sol-maintenance control.
These are reused development functions, not fresh validation or replication of
TokenEconomizer's277-task SWE-bench experiment. Do not pool the two interfaces.

Luna reduced observed Smallville maintenance cost by **93.29%** and total remote-model inference
cost by **46.31%**against the later Sol-maintained control. Nevertheless
Smallville/Luna cost **18.43% more than ordinary source search**. Making background
maintenance cheap did not establish an economical end-to-end memory system.

The TE/Luna arm passes the numerical development gate, but neither TE arm
injected a skill, applied pruning or issued a loop redirect. Its observed 12.05%
reduction therefore does **not establish a learned-memory benefit**; cache,
output and stochastic run differences remain possible explanations. All methods
hit the quality ceiling on these tiny functions. The separate memory-only block
also had8/8passes per arm and no candidate met its economic gate. No90%total-
inference saving, broad quality retention, deployment or cash/quota claim follows.

Natural reflection triggered **zero times in every coding arm**. Luna's separate
forced diagnostic produced 15 evidence-linked thoughts and exact recall after an
explicit output-format compatibility fix. It exposed substantial repetition and
one overly categorical causal inference. Evidence links are provenance, not
proof that a reflected claim is true. Benchmark reflection benefit is unmeasured.

## Comparable first benchmark

[Frozen development protocol](../../tools/usage-monitor/studies/luna-memory-tokeneconomizer-protocol-002.json)
selects eight public HumanEval tasks by a fixed hash, before outcomes. All methods
use the same Sol solver, task order, actor tools, source archive and independent
tests. Four arms compare ordinary source search, original-style Smallville with
Luna maintenance, and upstream TokenEconomizer micro-skills with Sol or Luna
maintenance. This isolates model choice from the memory algorithm. All scoring,
reflection, proposition and solving inference counts toward each arm's cost.

This is an adapted sequential coding development test, not official HumanEval
Pass@k, a reproduction of TokenEconomizer's SWE-bench/Web-Bench results, or a
comparison with its whole plugin. Micro-skills alone must be named as such.
The short single-repository function stream limits the opportunity to learn
durable repository facts; count actual injected facts and natural reflections,
and report abstention rather than inventing helpful setup failures. A full
product comparison needs separately verified native hooks, real capability
pruning/loop redirects and longer multi-repository task streams. No prior
benchmark percentage is compared directly against these new measurements.
