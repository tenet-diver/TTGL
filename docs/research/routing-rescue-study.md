# Does routing rescue small-model failures?

## First voluntary Pro router episode

Exactly one new voluntary router assignment ran on the first reserved NodeBB
SWE-bench Pro development task. Initial official grading and independent pristine
replay both pass: **1/1**, with one Luna controller invocation and **zero Sol
requests**. Completed setup008 (including two earlier expert consultations) was
reused after auditing 60 pinned artifacts, source bindings, sealed patches and
cumulative-thread metering. No setup model call was repeated. A fresh model-free
actor isolation probe passed before the scored call. See the
[episode audit](../../results/router-development-010-analysis/README.md).

Measured input is 333,186 tokens including 301,184 cached; output is 2,402 tokens
including reasoning. The frozen published-rate inference scenario is
**USD 0.00741304 per assigned and resolved task**. Request elapsed time is
39.73 seconds; the actor phase including harness work is 54.15 seconds, and
initial generation start through fresh grading is 203.51 seconds. These measure
different work; none is pure model inference latency. Historical setup has a
separate scenario cost of USD 0.03098282; no new setup inference occurred.
Actual cash expense, subscription-quota saving, matched-Sol saving and relative
accuracy retention remain unknown. Hardware, orchestration and grading expenses
are not included in this model-inference scenario.

The 12 visible shell requests show a lint correction and successful final ESLint
and diff checks, but no endpoint test execution. Luna explicitly acknowledged
incomplete runtime verification before choosing complete. Since the independent
final grade passes, this is an acknowledged verification gap on a successful
episode, not an observed false-success claim or missed escalation. No functional
failure opportunities were observed during solving. Failure-detection recall,
expert handoff and integration quality are therefore not measurable here. Tool
syntax and lint corrections are not distinct semantic repair strategies.

The default 2–3 checked independent attempts applies before asking Sol, not a
requirement to invent more changes after every candidate. The next v5 addition
emphasizes discriminating behavioral checks and a useful response to a material
verification gap. It is prepared but unrun, with no demonstrated improvement and
no mandatory expert review. Handoffs still carry relevant source, candidate,
attempts, exact outcomes, lessons, ruled-out hypotheses and remaining questions.

One selected public development task establishes neither generalization nor the
joint 95/95 target. An illustrative iid exact-binomial 95% interval after one
success spans 2.5%–100%; this does not make the selected task a representative
population sample. All 24 validation cases remain untouched. No second router
assignment or standalone comparison was launched. The 141 Verified assignments
and historical 500-task replay remain separate evidence. The contribution remains
replication and controlled extension of related work, not architectural novelty.


The completed held-out policy resolves 8/11 versus Luna 7/11 and Sol 9/11,
missing the joint cost/quality target.
The next experiment therefore measures rescue directly, rather than treating
low cost or availability of an expert as a positive routing result.

## Larger bounded comparison

The already reserved SWE-bench Pro V2 panel has 12 development and 24 disjoint
validation tasks, spanning repositories and languages beyond the original
Verified pilot. The population is 642 tasks; this is a subset study, not a full
benchmark score. Before any Pro inference, `routing-protocol-002.json` supersedes
the unrun four-arm prompt matrix while retaining its 48-development and
72-validation assignment caps.

Development arms are standalone Luna, standalone Sol, optional Luna-to-Sol
routing, and required specialist review. All share v3 common verification
guidance, tools, time and feedback access. The required-review arm makes the
candidate and checks first, then must send at least one self-contained handoff.
Noncompliance stays in the quality denominator and is reported separately.
Required review is a diagnostic control, not evidence of autonomous routing.

If required review rescues Luna failures and optional routing does not, the
observations implicate consultation decisions. If neither helps, inspect context
selection, the expert response and integration. These are diagnostic patterns,
not randomized causal identification of each component. Separate matched Luna
and assisted attempts may also differ through sampling.

To reduce this ambiguity, save the assisted run's exact patch immediately before
its first expert response. A temporary Git index includes staged, unstaged and
untracked source changes without modifying the actor's real index. Host records
outside mounted logs retain the authoritative patch and hash. After generation,
publish a derivative `agent/pre-handoff.patch` for the unchanged official
`PatchReplayAgent` using `patch_name=pre-handoff.patch`. Independently regrade
both initial and final patches on pristine images. No initial or final grader
feedback reaches the solving controller. A within-run recovery is observed
repair, not proof it could not have happened with another Luna-only attempt.

Report paired Luna-fail/Sol-pass cases rescued, Luna successes lost, consultation
on those cases, pre-handoff failures repaired, pre-handoff successes regressed,
missing snapshot grades and required-review noncompliance. Unknown cost or
snapshot evidence remains unknown. `handoff_metrics.summarize` rejects duplicate
or incomplete four-arm blocks, rather than selecting favorable attempts.

Run one complete development task block after the existing empty/reference,
actor boundary, native metering and pristine replay gates, then inspect measured
cost and runtime before expanding to 12 tasks. Freeze the optional policy before
the 24-task validation panel. Do not automatically expand validation if there is
no credible rescue benefit on development; separately register further prompt
development instead of repeatedly tuning on sealed outcomes.

## Implemented checks versus results

`RoutingDiagnosticCodex` is a maintained-Harbor agent extension, not a replacement
grader. Eighteen checks pass in the actual Harbor runtime with scripted model
fixtures, a real temporary Git repository, transport checks and paired-metric
examples. They cover shared guidance, required-review permissions, snapshot
timing/index preservation, post-generation replay export and full native-usage
propagation. Pro actor boundary and task-quality trials are still pending.

A separate live native context-only handoff check did execute Luna, Sol and
Luna integration: three calls and one consultation, with complete per-model
native usage and reconciled deltas. Luna sent its proposed clamp function and
observations; Sol identified an additional floating-point edge case; Luna adopted
explicit branches. Six post-hoc sandbox checks found five passes for the initial
proposal and six for the integrated proposal. This small required-review fixture
demonstrates actual message transfer and integration. It is neither a benchmark
accuracy result nor an autonomous-routing result. Its early invalid task metadata
was rejected before any invocation, recorded, and corrected without repeating a
model call. See `results/handoff-mechanism-001/validation.json`.

The running Verified study and its frozen policy remain unchanged. The Aider
test-feedback diagnostic remains a separate reserved panel, with its own
controls and verifier corrections. Neither framework tests nor toy mechanism
checks are pooled into task-quality tables or the 95/95 target calculation.

### Local Harbor networking compatibility

The installed Docker Desktop kernel lacks the nftables FIB support required by
Harbor 0.25's egress sidecar. A custom environment extension uses Harbor's
supported import-path hook and maintained Docker network disconnect/connect
operations, retaining Harbor's lifecycle, exec, mounting and verification code.
It supports only public/no-network phases on one standard Linux task container;
allowlists, custom Compose topologies, Windows, published ports, elevated network
capabilities and exposed daemon sockets are rejected. Every transition inspects
actual container attachments before completing. A failed transition stops the
phase, so the actor cannot proceed on an unverified network change.

Real Harbor fixture evidence is separate from task readiness and model quality.
It checks public peer HTTP reachability, zero attachments and failed numeric-IP
peer access in the isolated phase, restoration of positive reachability, and
allowlist rejection. The actual Pro image, actor boundary and official empty/
reference controls must still pass before any model trial. Peer isolation is
not a universal egress proof; the registered actual actor probe remains required.

A separate task-local Docker configuration selects the installed Compose plugin
because the user's global plugin link points to a stale app-translocation path.
It contains no registry credentials and leaves the user's settings untouched.
The first official Pro no-op attempt and all failed fixtures remain archived.
