# Prospective reserved-library extension

Registered locally on 11 November 2026, before reserved solver inference.
[Protocol and randomized order](../../../experiments/codex-team-knowledge-001/reserved-factorial-protocol-001.json).
**Results: pending.** The completed two-library pilot remains a separate study.

The question is whether an added knowledge store helps native Codex teams when
there is a usable publication/retrieval procedure. The pilot observed publication
but no retrieval of peer observations, so availability alone cannot establish
useful accumulation. We freeze a factorial extension before observing reserved
agent outcomes.

| Factor | Values |
| --- | --- |
| Added store | Native channels and shared repository; same system plus official MCP memory |
| Usage guidance | Ordinary task instructions; explicit evidence/publication/retrieval/rechecking procedure |
| Total native capacity, including parent | 1, 2, 4, 8 |
| Reserved libraries admitted before inference | WCWidth, Cachetools, Voluptuous, IMAPClient, Babel |

This is **5 × 2 × 2 × 4 = 80 assignments**, one attempt per cell, with a fixed
randomized order. The earlier 36-task longitudinal design is a different study;
it does not justify this sample. Five repositories permit descriptive paired
estimates, not a powered claim about coding agents generally. Individual tests
are not independent experimental subjects.

Explicit guidance applies to both store conditions. It asks agents to publish
source-backed findings before dependent work, retrieve relevant peer findings
before interface changes/integration, distinguish proposals from observations
and recheck stale claims. MCP additionally uses a common `repository` entity
and its supported `open_nodes` interface; its search uses literal substrings.
This compares deployment policies, not storage representation in isolation.
Native chats, inherited context, shared code and spontaneous notes remain
available in every condition. Codex itself decomposes, delegates and integrates;
there is no custom supervisor. Actual thread counts are measured: the primary
intervention offers capacity, rather than forcing an exact worker count. The
[official Codex reference](https://learn.chatgpt.com/docs/config-file/config-reference)
defines the concurrent spawned-thread limit as excluding the primary thread;
we set it to total capacity minus one and also inspect actual runtime evidence.

| Library | Untouched reference checks | Preparation |
| --- | ---: | --- |
| WCWidth | 38 pass, 1 skip | Matching distribution metadata; Python 3.11 |
| Cachetools | 215 pass | Source layout preserved |
| Voluptuous | 149 pass | In-package tests restored independently |
| IMAPClient | 267 pass | Original public test directory |
| Babel | 6,700 pass, 6 skips | Pinned published CLDR data only; no implementation copied |

All blank controls fail. Seven other reserved libraries fail source/security or
environment admission and remain excluded without replacements: Deprecated,
Marshmallow, PyJWT, MiniTorch, Parsel, Chardet and Portalocker. Their failed
preparations are retained and are not solver failures. Graphiti's small local
CPU configuration fails fact fidelity; Cognee's compatible dependency graph
remains blocked. Neither receives a coding score.

Every cell uses GPT-6.1 Sol at low reasoning, 30 minutes, 120 shared terminal
calls, two container CPUs and 2 GiB memory. A four-million observed-token stop
threshold can be exceeded by in-flight work. The Python 3.11.18 profile and
[25-package lock](../../../experiments/codex-team-knowledge-001/reserved-runtime-001.lock)
are declared compatibility variants; no XML stack or Setuptools is installed.
Stores and native homes begin fresh. Assignment/provider retries are zero.

The primary outcome is sealed source-only test resolution, with original tests
and fixed resources restored. Collection must meet the reference count and
unexpected skips cannot create a success. New tests/generated files are excluded
from replay; modifications to existing tests/configuration are separately
flagged. Zero-inference witnesses verify that poisoned actor tests/data are
restored, a reference implementation passes and a blank implementation fails.
All five tasks pass both native and container boundaries before inference.

Report paired successes gained/lost, all-cell elapsed run time, native parent
completion, observed test-pass fraction, total inference where measurable and
explicit lower bounds elsewhere. Compare store effects at each capacity within
each guidance level, then their interaction. Do not compare only successes or
rank overlapping unknown cost bounds. Cost per resolution is undefined at zero
success. Publication, exact peer exposure and useful verified action are separate
mechanism claims. Encrypted native messages limit content analysis.

Full raw evidence remains in the persistent workspace, with verified lossless
archives after each cell. A hard free-space gate stops before new inference;
no unique evidence is deleted to make a result look complete. Analysis may be
updated after generation; prompts, assignment order and replay policy stay frozen.
